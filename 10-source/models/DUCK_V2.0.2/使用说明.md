# Xduck MJCF：2026-11-07 装配更新

基于用户提供的 `Xduck_橙色整机_检查版双脚镜像.solidcraft` 更新已确认的训练碰撞精简版。更换双脚、机身上盖、加厚电路保护壳、机壳和主控板，加入本次装配中的安装桥板、开关、显示模块等参考外形。机身上盖采用该装配体当前导出的网格，原颜色保留，其训练碰撞顶部包络同步按当前外形拟合。保留原头颈机构、下半身电机显示和已确认关节限位。原装配文件与旧版 MJCF 均保留。

交付文件夹根目录包含 `scene.xml`、`robot.xml`、`assets/`，可以直接选择这个文件夹上传；所有加载依赖都在文件夹内，XML 使用相对路径。

## 入口和初始姿态

- `scene.xml`：完整外观，碰撞使用精简代理。
- `scene_train.xml`：训练入口，编译时舍弃外观；物理参数和传感器与外观入口一致。
- `view_model.py`：运动学检查查看器，Control 滑块直接设置角度，不运行站立控制器。

解压后的文件夹中使用：

```sh
mjpython view_model.py
mjpython view_model.py --home --upper-cover
mjpython view_model.py --home --neck-adjust
mjpython view_model.py --home --knee-adjust
mjpython view_model.py --ankle-zero
mjpython view_model.py --collision
mjpython view_model.py --self-collision
mjpython view_model.py --overlay
```

查看器默认显式加载 `ASSEMBLY_INITIAL`。其他训练程序也应显式选择该关键帧；普通 XML 加载不会自动执行关键帧。

`neck_pitch` 的正式限位已按用户调姿结果更新为 **-0.45～+1.3 rad**，关节 range 和执行器 ctrlrange 一致，HOME 姿态保持原值。正常查看使用 `mjpython view_model.py --home`。

`--neck-adjust` 仅用于继续调姿，会在当前查看器内临时放宽为 -1.3～+1.8 rad；该临时范围不是正式 XML 的限位。查看器使用完整不透明外观。

`--knee-adjust` 将左右 knee_pitch 关节和 Control 滑块的当前调试范围临时放宽为 -2.5～+2.5 rad，方便核对膝关节新的限位。正式 XML 的膝限位仍保留原值；neck_pitch 保持已确认的 -0.45～+1.3 rad。

```python
import mujoco
model = mujoco.MjModel.from_xml_path("scene_train.xml")
data = mujoco.MjData(model)
mujoco.mj_resetDataKeyframe(model, data, model.key("ASSEMBLY_INITIAL").id)
mujoco.mj_forward(model, data)
```

`ASSEMBLY_INITIAL` 保留当前装配的实际站姿：neck_pitch=-0.26 rad，head_pitch=-0.24 rad；左踝约 -0.455003758 rad、右踝约 +0.455003739 rad。其他腿部角度保持此前设定。

`ANKLE_ZERO_CHECK` 将两踝设置为 0，其他角度沿用装配站姿。`MECHANICAL_ZERO` 将脖子 pitch、头 pitch 和两踝设置为 0，其他腿部角度仍保留装配值。它们是定位核查姿态，不是所有关节全零姿态；为避免倾斜脚底穿入地面，机身抬高 20 mm。它们不用于站立训练初始化。

旧 `HOME` 和 `GAIT_REFERENCE` 保留；后者初始脚底约有 8.95 mm 地面穿入，只作历史动作参考，不作为接触训练初始状态。

## 脚部机械零点

采用新脚安装耳直径 3 mm 孔与原小腿定位孔同轴的姿态定义踝关节 0 rad。分别从左右脚当前网格、小腿网格拟合孔轴，确认孔轴对齐时侧视夹角约 90°。与原踝关节零位的数值差仅约 0.000004 rad；已同步换算关节 ref 和保存的初始角度，装配站姿没有被旋转。

这里的 90° 是垂直踝轴观察的侧视定义。原装配中踝轴存在约 4.584° 倾斜，鞋底曾做水平处理，因此不能声称实际鞋底平面与小腿长轴的三维夹角严格为 90°。本次遵循定位孔对齐，不修改 CAD 几何来消除该差异。

见 `双脚机械零点核查.png`、`ankle_zero_calibration.json`。孔轴误差是网格拟合的计算结果，不代表加工公差。

## IMU 测量点和坐标系

按用户确认，将整个水平 IMU 绕外形中心、沿机身 Z 方向掉头 180°，安装中心保持不变。用户最终明确测量原点应在 IMU 左右中线、靠机身前方的位置；采用外形中心沿机身 +X 偏移 14 mm、距前缘约 6 mm 的点，厚度取中面。此定义覆盖之前把原点推算到后侧的错误。朝向修正覆盖所提供装配中 IMU 参考外形的朝向，原 SolidCraft 文件不修改。

最终轴向以用户明确指定的关系为准，独立于旧外形变换推算：

| IMU 正轴 | 对应 base_link 方向 |
| --- | --- |
| +X | -X |
| +Y | -Y |
| +Z | +Z |

两者都是右手系。IMU 到 base_link 的旋转矩阵为 `diag(-1,-1,1)`，四元数 wxyz 为 `(0,0,0,1)`。

测量点相对 base_link 为 **(-30.000, +6.000, -2.627) mm**；精确值见 `IMU坐标配置.json`。它在 IMU 外形厚度中面、距机身前方 +X 侧外缘约 6 mm。IMU body 与名为 `imu` 的 site 同原点、同方向，site 的局部位置与姿态为单位变换。base_link 仍是原机身参考点。

实体 IMU 的 `orientation`、`angular-velocity`、`imu_accel` 使用上述新测量坐标。保留另一个独立的 `policy_aligned_imu` 虚拟 site，与 base_link 同原点同轴；`imu_upvector`、`imu_ang_vel`、`imu_lin_vel` 仍引用这个虚拟观测坐标，避免改变旧策略的观测语义。接入真实传感器时必须区分这两组通道。

主控板 `control-box` 的 152 g 质量位置已跟随当前装配更新；电池下方电路板 `power-strip` 的 91 g 保留在其原安装位置。IMU 的 30.45 g 质量及几何估算惯量随新位置与朝向更新。

## 重量和惯量

左右脚各 **189 g**（按用户最新值，从各 176 g 更新）；机身原总重 1029.25 g 增加用户指定的 30 g，更新为 **1059.25 g**；整机总重 **10.29314 kg**。其他部件沿用之前确认的各部分总重，不按外形体积分配新增质量。`各部件重量.csv` 列出各 MJCF body 的总重。

新脚是开放检查网格。使用 189 g 总重与均匀表面积分估算质心、惯量，不将开放网格的有符号体积当成可靠实体体积。本次外形与质心位置不变，脚部惯量按 189/176 的质量比例同步更新。机身新增 30 g 的分布未测量，暂保留原机身质心、按质量比例缩放惯量。IMU 和主控板按闭合参考外形估算质心、惯量。以上均不是实测惯量。

## 碰撞和检查

保留训练精简方案，更新新脚脚底轮廓、踝部包络和加厚保护壳包络，并为后方显示模块增加一个环境碰撞盒。共 **37 个机器人碰撞体**；训练入口含地面共 38 个 geom、10 个碰撞网格、636 个碰撞顶点。内部 IMU、主控板、桥板等不另做细碎碰撞。
