## 实际训练谱系

```text
v2.0.2随机初始化
→ 基础五阶段：1000 + 500 + 500 + 400 + 100 = 2500次更新
→ 坐姿头颈残差修复200次
→ 冻结接入历史原1.1.2 B2500的完整14轴起立网络（不新增训练）
→ 坐下过渡残差300次（仍磕头）
→ 递进复位课程继续600次（名义坐下不再磕头）
→ 坐姿头颈支撑残差400次
→ support400/final.pt → 单个ONNX → 桌面v1/xc_site.onnx
```

| 基础阶段 | 新增更新 | 内容 |
|---|---:|---|
| 0→1000 | 1000 | 随机初始化；新模型、新承重坐姿及高度适配；原奖励与课程 |
| 1000→1500 | 500 | DR配置范围扩大至原范围2倍 |
| 1500→2000 | 500 | DR配置范围扩大至2.5倍 |
| 2000→2400 | 400 | 收紧下降速度，增加逐头关节误差及头部终点精修 |
| 2400→2500 | 100 | 原站立教师软成本、起立奖励目标渐变1.2秒；选取B2500 |

第5阶段原配置预算为200次，本次在完成前100次、确认B2500检查点完整后停止，因此配置和实际所选更新数不同。基础actor从随机初始化；第5阶段仍按原方案使用冻结教师相关软成本。

新v2.0.2谱系合计 **4000次PPO更新**，基础阶段4096环境、修复阶段2048环境，均为24步rollout。累计新增环境采样319,488,000次。它包含不同冻结范围、不同批量的局部修复，不能称为单个全参数策略训练至“B4000”；旧起立网络的历史2500次训练另计。预检、未采用实验及停止的standing100不计入该谱系。

最终起立分支来自原 **1.1.2 B2500**，不是1.1.4 B2700。坐姿头颈支撑400次训练协调14轴残差；已有下降、起立和基础网络的权重冻结。一个ONNX中包含多条网络分支与门控，不是通过蒸馏重新训练成单个MLP。

## 物理模型、控制与课程

- v2.0.2刚性模型：14主动轴，nq21/nv20，质量约10.29314kg。
- 物理步长1ms，控制周期20ms，actor输入61、critic输入76、动作14。
- 基础Actor/Critic为512/256/128、ELU；actor无外部归一化。
- 目标增量解码为 `clip(previous_target + increment * tanh(raw_actions), low, high)`。
- 新坐姿腿部参考为 `[0,0,0.696,-1.05,-0.263, 0,0,-0.696,1.05,0.263]` rad。
- 奖励站高/坐高为0.3228203088/0.2242745990m，均指基座高度。HOME是初始化/站立参考，不能当作编码器零点。

基础阶段恢复原五阶段的DR范围课程；后续头颈200次使用较小DR，坐下300/600次及支撑400次以名义物理条件训练，只有小幅复位扰动，**没有重新覆盖原2.5倍DR，更没有将真机阻尼/限矩问题训练回模型**。额外延迟设零仍保留原通信时序模型，不等于绝对零延迟。

600次坐下修复使用由近及远的复位课程：70%当前前沿、20%完整站姿、10%坐稳姿态；至少256回合、近期无违规成功率达到80%才推进。中间姿态只用于初始化，之后全程PPO控制；没有规定执行关节轨迹或外力辅助。

详细奖励、冻结范围、学习率、课程与哈希见训练说明和9份原配置。

## 仿真结果与真机限制

最终标准8条轨迹完整坐下、坐姿头颈、起立和再次坐下均通过；扩展6类头颈指令各8条，共48条：

- 48/48头颈运动无违规触地；96/96坐下无磕头并坐稳；48/48起立无违规触地。
- 扩展四轴跟随MAE约1.79°/4.23°/2.03°/2.64°；负向保持时头pitch误差约7.72°。
- ONNX与67,200条验证观测对应动作最大误差约3.04e-6。

这些是名义仿真重复，不是多个独立训练种子或真机通过率。最终模型的快速反向/连续切换/延迟压力验收没有由更早ONNX的测试自动继承。

真机两次坐下片段出现折膝后俯仰扩大、随后反向倾倒。部署消费者离线重放268帧目标最大误差约1.19e-7rad。1200条冻结策略因素扫描中，Kd减半加仿真净输出限矩12Nm的同批32次对照有25次出现同类后倒；两项单独施加均无严重倾倒。IMU额外延迟40或60ms也各有3/16出现同类失稳。这些是可复现机制，**不能推断真实Kd被减半或实际限矩就是12Nm，也尚未唯一锁定硬件根因**。

## 部署配对与版本元数据

`policy/xc_site.onnx` 和 `xc_site.py` 按用户实际部署文件原样保存。消费者的执行代码、运行参数与support400交付版一致，但其内嵌IO的版本名称、检查点及模型哈希仍写着旧descent600；这些字段未被该Policy类的推理路径读取。真实模型身份以文件SHA和本目录谱系为准，静态核验记录保留了差异。

配套JSON/YAML来自最终support400导出，保留其原导出文件名 `xduck_v202_support400.onnx`；本仓库/桌面同一模型命名为 `xc_site.onnx`。加载时使用实际配对文件名，不要将旧元数据当作选择旧权重的依据。

网络输入必须是躯干坐标系IMU角速度和单位重力、模型坐标关节反馈；实体IMU外参、编码器零点、方向、底层实际增益和限流仍需单独核对。切换sit/rise时保持目标积分连续，旧HOME换算已经在ONNX内部。`xc_walk_stand.py` 不属于本目录的坐起消费接口，不能因维度相同而互换。
